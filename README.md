# mlx-rs, forked to build off Apple silicon

Two crates from [oxideai/mlx-rs](https://github.com/oxideai/mlx-rs), patched to
build on Windows and Linux, on x86, and against CUDA. Upstream builds on Apple
silicon against Metal.

0.25.3 and 0.2.0 are the newest published versions of either, and neither
declares a `cuda` feature.

## Layout

`mlx-rs` names both the upstream repository and one of the two crates in it.
That is upstream's arrangement and this mirrors it, which is why there is an
`mlx-rs/` directory inside a fork called mlx-rs.

```
mlx-rs-stemd/
├── mlx-rs/            safe Rust API        (crates.io: mlx-rs 0.25.3)
└── mlx-sys/           raw FFI, bindgen     (crates.io: mlx-sys 0.2.0)
    └── src/mlx-c/     Apple's C API, vendored inside the crate
```

Four layers, bottom up:

| | |
|---|---|
| **MLX** | Apple's C++ library. Not in this repository; CMake fetches it at build time. |
| **mlx-c** | Apple's C API over MLX. Vendored at `mlx-sys/src/mlx-c`, taken from `ml-explore/mlx-c` rather than from the copy mlx-sys shipped. |
| **mlx-sys** | Raw Rust FFI, generated by bindgen from mlx-c's headers. Owns the build script. |
| **mlx-rs** | Safe Rust over `mlx-sys`. What a consumer depends on. |

`mlx-rs/README.md` and `mlx-sys/README.md` are upstream's, unmodified. They
describe the crates, not this fork.

## Contents

Six commits, each one change, each checkable against a published source.

| | |
|---|---|
| Import as published | byte for byte from crates.io |
| Take mlx-c from upstream `fba4470` | the bundled copy predates the CUDA backend |
| Half types on x86 | mlx-c declares `float16_t`/`bfloat16_t` on aarch64 only |
| Array entry points | the newer mlx-c moved the API out from under 0.25.3's bindings |
| mlx-rs to suit | five files of signature work |
| Build off Apple | one `build.rs` for macOS, MSVC and Linux; patches CUTLASS and MLX's RMSNorm at configure time |

## Use

```toml
[patch.crates-io]
mlx-sys = { path = "vendor/mlx-rs-stemd/mlx-sys" }
mlx-rs  = { path = "vendor/mlx-rs-stemd/mlx-rs" }

[workspace]
exclude = ["vendor"]
```

`exclude` is required: cargo otherwise claims these as workspace members.
There is no workspace manifest at this repository's root, for the same reason.

Select CUDA with `MLX_BUILD_CUDA=1` rather than the `cuda` feature when consuming
transitively, since a feature cannot be set on a transitive dependency from the
consuming manifest. `metal` is gated on being on Apple, so asking for it
elsewhere yields a CPU or CUDA build rather than a failure.

A first build compiles MLX and CUTLASS from source. Budget forty minutes.

## Known limitations

- `ScaledDotProductAttentionMask::Arrays(masks)` degrades to `masks.first()`.
  mlx-c 0.6.0 takes a single mask; the variant can no longer be expressed.
- CUTLASS does not compile under MSVC 19.44 at any released version, v4.4.2
  through v4.7.0 (`cute/stride.hpp:299`, error C3545). `build.rs` renames the
  colliding alias.
- The RMSNorm cherry-pick is upstream in v0.32.0 and is carried only until the
  pinned MLX moves past it.

## Upstreaming

The x86 half types and the cross-platform `build.rs` are generic and belong
upstream. The array and signature commits are better fixed by regenerating
`mlx-rs`'s bindings against current mlx-c.
